## 1. What Batuta is

The **open measurement layer for Agent Skills**: measures whether a skill actually works,
at what cost, and on which model — and publishes everything, immutable, zero-profit.

It's not another router. It's **the judge**, and it works with any router. The 26
competitors from GitHub's `skill-router` topic become 26 integrations, not 26 rivals.

**Sequencing rule (not reversible):**

1. measure code skills and publish the data — prove it first
2. cheap recipes perform as well as expensive ones — prove it with a number
3. global public infrastructure — the mission, which 1 and 2 buy the right to announce

## 2. Decisions made THIS session

| # | Decision | Why |
|---|---|---|
| 1 | Repo at `github.com/filipecrocks/batuta`, **public** | faster; can be transferred to an org later without losing anything |
| 2 | Portal on **Vercel**, database on **Neon**, domain **batuta.space** | Filipe's choice this session; the VPS stays out of it |
| 3 | The Rust binary **doesn't touch the network. Ever.** | makes the hot path auditable by inspection: there's no socket to review. The npm wrapper is what downloads the public registry |
| 4 | Index in a **custom line-by-line format**, not JSON | the hot path has a 100ms total budget; only the postings for the query's terms need to be opened. JSON would force parsing the whole file |
| 5 | **Zero dependencies** in the Rust crate (not even sha256, not even JSON) | ~600 auditable lines, static binary, 1 to 3ms startup |
| 6 | The block injected into context is **short**; the full disclosure (privacy, opt-in, holdout) appears **once**, on first run | each skill costs ~53 tokens per turn; a disclosure repeated on every turn is a tax |
| 7 | `install-hooks` does **not** edit `settings.json` on its own | touching the agent's config without the user seeing it is the kind of thing this project doesn't do |
| 8 | Portal with **just one npm dependency** (`@neondatabase/serverless`) — markdown rendered by 150 lines of our own | in a project whose product is credibility, cheap auditing matters |
| 9 | Without `DATABASE_URL`, queries return an **empty list** instead of blowing up | the portal needs to build on Vercel **before** the database exists |
| 10 | Empty pages say they're empty, with the reason | publishing a made-up number would kill the project; it's the only product it has |
| 11 | Minimum ranking cutoff: **3 distinct installs** per skill | a row from a single machine is an anecdote, and publishing an anecdote as a ranking is the mistake we accuse others of |
| 12 | The `instalar.sh` served at `batuta.space/instalar.sh` is **the exact same file from the repo** | in a `curl \| sh`, that's what separates trust from asking for trust |
| 13 | Secrets **never pass through chat** — not even to me | rule zero of the vault. The deploy path was redesigned so that no value ever travels |

## 3. What's DONE — measured, not estimated

### 3.1 Hot-path Rust binary — `crates/batuta/`

Commands: `index`, `route`, `log`, `report`, `resumo`, `find`, `conflicts`, `config`,
`privacidade`, `install-hooks`, `version`, `help`.

| file | what it does |
|---|---|
| `src/texto.rs` | tokenizer: doubled accents, glued words stripped, loose numbers stripped, 5-letter prefix instead of a stemmer |
| `src/indice.rs` | scans `SKILL.md`, reads frontmatter, builds the inverted index; **partial read** of only the query's terms |
| `src/bm25.rs` | K1=1.5, B=0.75, noise cutoff 2.0, cap of 3 suggestions, top-fraction 0.55 |
| `src/rota.rs` | hot path: holdout, scoring, injected block, event |
| `src/registro.rs` | JSONL events, report (funnel, ghost, cost/task, lift), and the aggregated daily summary |
| `src/casa.rs` | `~/.batuta`, salt at 0600, config, install id derived from the salt |
| `src/achar.rs` | `find` — installed → available → gap, ranked by full text |
| `src/conflitos.rs` | skills competing for the same turn (idea from SkillPilot, MIT, credited) |
| `src/sha256.rs`, `src/json.rs`, `src/data.rs` | zero dependencies, by project rule |

**Proof, run this session:**

```
cargo fmt --check                      → clean
cargo clippy --all-targets -D warnings → clean
cargo test -- --test-threads=1         → 16 of 16 green (15 from the battery + 1 unit test)
```

**Measured performance:**

| | |
|---|---|
| indexing 506 skills | **91 ms** |
| 50 routes, including process startup | **136 ms** total (~2.7 ms each) |
| algorithm only, 506 skills | **0.03 ms** per route |
| index size | 397 KB |

The budget was 100 ms per turn with a hard cap of 300 ms. That leaves two orders
of magnitude of headroom.

**Real bug found and fixed this session:** salt generation was reading the
entirety of `/dev/urandom` with `fs::read`. `/dev/urandom` **has no end** — the process ate all the
machine's memory and died. It became a 32-byte read. The comment in the code tells
the story, so nobody "optimizes" it back.

### 3.2 Conformance battery — `crates/batuta/tests/conformidade.rs`

15 tests that are **the contract**. A port to another language is conformant when it
passes this battery with the same numbers. Runs with `--test-threads=1` (the tests
share the same temp home via `BATUTA_CASA`, which is process-global state).

Among other things, these lock down: the BM25 parameters, silence on noise, the
holdout's determinism and its ratio across 2000 draws, and the fact that the
prompt's text **doesn't appear** in the event.

### 3.3 Battery v1 — `bateria/v1/tarefas.json`

24 frozen tasks: 6 categories × 4 (1 simple, 2 medium, 1 complex). The 4
`codigo` ones have an automatic verifier. **The 21 verifiers were actually tested**:
a reference solution was written for each one, and all of them pass the reference and
fail when the solution is removed (negative control). One real hole was found and
corrected in this process (`cod-04`'s "True ≠ 1" rule was slipping through undetected
via dictionary comparison).

### 3.4 Protocol — `docs/PROTOCOLO.md`

Batuta Zero as a numbered procedure: 5 tasks × 4 models × 2 arms = 40
runs. Seed published and committed before the first run; order randomized via
`sha256(SEED|tarefa|modelo)`; clean session checked; anonymization with an opaque code and a
hash-sealed map **before** judging; publication of the raw data. Plus the judge (three laws,
cross-judging pairs, a 3-axis rubric per category) and the causal holdout.
Every shell command in the document was actually run before going into the file.

### 3.5 Neon database — `sql/`

10 tables in `sql/001_inicial.sql` plus `batuta.recalcular_metricas_dia(date)`,
idempotent. `sql/002_cadeia.sql` has triggers that block **UPDATE, DELETE, and
TRUNCATE** on `batuta.registros`, and `batuta.verificar_cadeia()`.

**A local Postgres 16 was spun up and everything was applied, reapplied, and
exercised with data.** Resending the same day genuinely replaces instead of duplicating;
all three forms of tampering raise an exception.

Three constraints become database law: `juiz_modelo <> modelo`, a judge without a
version or without a prompt hash is rejected, and a task only leaves triage with a
canonical statement and acceptance criteria.

### 3.6 Portal — `portal/`

Next.js 15 App Router, TypeScript, **clean build: 18 routes**, all static except the
two API ones.

| route | status |
|---|---|
| `/` | done — honest scoreboard, the three pieces, where it's headed |
| `/manifesto`, `/spec`, `/protocolo` | done — render the repo's markdown |
| `/ranking` | done — empty with the reason written; bias declared upfront |
| `/receitas` | done — empty with the reason written |
| `/arena` | done — working form + queue |
| `/registros` | done — the three anchors, and what the chain does NOT prove |
| `/privacidade` | done — table of what stays, example of what's uploaded, how to delete |
| `/instalar`, `/creditos`, `/doar`, `/404` | done |
| `/api/ingest`, `/api/arena` | done — **23 test cases** against the real handlers |
| `/instalar.sh` | serves the exact same file from the repo |

`/api/ingest` **rejects any payload containing `prompt`, `prompt_hash`, `turno`,
or `texto` at any level**, even if the schema would otherwise pass: if a raw event
arrived, that's a client bug, and the response says so.

**Visual review done**, not just the build: pages captured at 1280px and at 390px
and opened one by one. Two real defects were found and fixed this way — a shorthand
`padding` on the opening section zeroed out the side breathing room on mobile (the text
hit the edge), and a list item that wraps to two lines in markdown was letting the end
of the sentence turn into a stray paragraph.

### 3.7 Distribution — `npm/`, `script/`, `.github/`

`script/instalar.sh` in pure POSIX, with **SHA256 verification** against the
release's `SHA256SUMS` (doesn't match, doesn't install). `npm/` with zero dependencies:
opens tar.gz and zip in pure JS. Two workflows: `release.yml` (5 targets,
consolidated `SHA256SUMS`) and `prova.yml` (fmt + clippy + tests).

**Tested end to end with a local HTTPS server and a fake release:** good install,
tampered SHA rejected with exit 1, Windows zip extracted, wrapper passing through the
exit code.

### 3.8 Hash chain — `script/cadeia.mjs`, `registros/`

`anexar`, `verificar`, `ots`. The canonical JSON **matches byte for byte** with
Rust's `json::escrever` — checked against 5 real outputs. All 4 forms of tampering
(content, removal, TOPO, a date outside the seal) were caught with the exact position.

## 8. Blockers that came up this session — so the next chat doesn't trip on them

1. **This session's GitHub token is read-only for public repos.** The API responds
   *"sessions are bound to their configured repositories"* and `git push` has no
   credential. That's why the repo wasn't created from here. In a chat with the repo
   already existing and access granted, the push goes straight through.
2. **There was no bridge to Filipe's PC or the VPS.** Neither `device_bash` nor
   Desktop Commander (its skills show up in the list, but the **MCP isn't
   connected** — and without a server, the instruction doesn't execute). So
   `source bin/cofre.sh` wasn't possible.
3. **The connected Lumaro MCP was `5550cdfb…` — the legacy one.** Writing a document
   there disappears from 7.7. Lumaro went down mid-session; the handoff went to Google
   Drive.
4. **`project_write` doesn't exist in this session.** If the next chat has it, that's
   how the document gets into the project.
5. **A background process dies between shell calls** in this container. A test
   server needs `setsid nohup`, and even then it's fragile.
6. **Two `next start` processes at the same time serve different builds** and the
   CSS comes back 400 — the page opens with no styling at all and looks like a CSS bug.
   Kill the old one first.

## 9. The project's laws that the next chat can't break

1. **Zero profit.** Nobody makes anything.
2. **The prompt never leaves the machine.** Hashed with a local salt, and the salt
   isn't sent.
3. **The binary doesn't touch the network.** If it needs the network, it doesn't live
   in the binary.
4. **Silence on noise.** A false positive costs more than a false negative.
5. **A vote decides the queue, never the score.**
6. **The judge is blind, isn't the defendant, and is versioned.**
7. **A control group exists** — 5%, disclosed, configurable, can be turned off.
8. **The chain doesn't get edited.**
9. **Bias disclosed, always.**
10. **Source before build** — no published artifact without a remote that's been
    pushed to.
11. **Numbers are measured, not estimated.** If n is small, say n. "I don't know" is
    a valid answer.
12. **Secrets live only in the vault.** Secrets are never requested or pasted into
    chat.
13. **When declining or limiting something, the reason gets written down. When
    publishing, the raw data comes along.**
