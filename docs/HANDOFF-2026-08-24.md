## 1. O que é o Batuta

A **camada aberta de medição de Agent Skills**: mede se uma skill funciona de verdade,
a que custo e em qual modelo — e publica tudo, imutável, sem lucro.

Não é mais um roteador. É **o juiz**, e funciona com qualquer roteador. Os 26
concorrentes do tópico `skill-router` do GitHub viram 26 integrações, não 26 rivais.

**Regra de sequência (não se inverte):**

1. medir skills de código e publicar o dado — provar primeiro
2. receitas baratas rendem igual às caras — provar com número
3. infraestrutura pública global — a missão, que 1 e 2 compram o direito de anunciar

## 2. Decisões tomadas NESTA sessão

| # | Decisão | Por quê |
|---|---|---|
| 1 | Repo em `github.com/filipecrocks/batuta`, **público** | mais rápido; dá para transferir para uma org depois sem perder nada |
| 2 | Portal na **Vercel**, banco no **Neon**, domínio **batuta.space** | escolha do Filipe nesta sessão; a VPS fica fora |
| 3 | O binário Rust **não acessa a rede. Nunca.** | torna o caminho quente auditável por inspeção: não existe socket para revisar. Quem baixa o registro público é o wrapper npm |
| 4 | Índice em **formato próprio linha a linha**, não JSON | o caminho quente tem 100ms de orçamento inteiro; só as postings dos termos da consulta precisam ser abertas. JSON obrigaria a parsear o arquivo todo |
| 5 | **Zero dependência** no crate Rust (nem sha256, nem JSON) | ~600 linhas auditáveis, binário estático, subida de 1 a 3ms |
| 6 | O bloco injetado no contexto é **curto**; a declaração completa (privacidade, opt-in, holdout) aparece **uma vez**, na primeira execução | cada skill custa ~53 tokens por turno; declaração repetida em todo turno é imposto |
| 7 | `install-hooks` **não** edita o `settings.json` sozinho | mexer na configuração do agente sem o usuário ver é o tipo de coisa que este projeto não faz |
| 8 | Portal com **uma dependência npm só** (`@neondatabase/serverless`) — markdown renderizado por 150 linhas nossas | num projeto cujo produto é credibilidade, auditar barato importa |
| 9 | Sem `DATABASE_URL`, as consultas devolvem **lista vazia** em vez de explodir | o portal precisa buildar na Vercel **antes** de o banco existir |
| 10 | Páginas vazias dizem que estão vazias, com o motivo | publicar número inventado mataria o projeto; é o único produto que ele tem |
| 11 | Corte mínimo do ranking: **3 instalações distintas** por skill | linha com uma máquina só é anedota, e publicar anedota como ranking é o erro que acusamos nos outros |
| 12 | O `instalar.sh` servido em `batuta.space/instalar.sh` é **o mesmo arquivo do repo** | num `curl \| sh`, isso separa confiança de pedido de confiança |
| 13 | Segredo **não passa por chat** — nem para mim | lei zero do cofre. O caminho de deploy foi redesenhado para nenhum valor viajar |

## 3. O que ESTÁ PRONTO — medido, não estimado

### 3.1 Binário Rust do caminho quente — `crates/batuta/`

Comandos: `index`, `route`, `log`, `report`, `resumo`, `find`, `conflicts`, `config`,
`privacidade`, `install-hooks`, `version`, `help`.

| arquivo | o que faz |
|---|---|
| `src/texto.rs` | tokenizador: acento dobrado, palavra-cola fora, número solto fora, prefixo de 5 letras no lugar de stemmer |
| `src/indice.rs` | varre `SKILL.md`, lê frontmatter, monta índice invertido; **leitura parcial** só dos termos da consulta |
| `src/bm25.rs` | K1=1.5, B=0.75, corte de ruído 2.0, teto de 3 sugestões, fração do topo 0.55 |
| `src/rota.rs` | caminho quente: holdout, pontuação, bloco injetado, evento |
| `src/registro.rs` | eventos JSONL, relatório (funil, fantasma, custo/tarefa, lift) e o resumo diário agregado |
| `src/casa.rs` | `~/.batuta`, sal 0600, config, id de instalação derivado do sal |
| `src/achar.rs` | `find` — instalada → disponível → lacuna, ranqueando por texto completo |
| `src/conflitos.rs` | skills que competem pelo mesmo turno (ideia do SkillPilot, MIT, creditada) |
| `src/sha256.rs`, `src/json.rs`, `src/data.rs` | zero dependência, por lei do projeto |

**Prova, rodada nesta sessão:**

```
cargo fmt --check                      → limpo
cargo clippy --all-targets -D warnings → limpo
cargo test -- --test-threads=1         → 16 de 16 verdes (15 da bateria + 1 unitário)
```

**Desempenho medido:**

| | |
|---|---|
| indexar 506 skills | **91 ms** |
| 50 rotas, subida de processo incluída | **136 ms** no total (~2,7 ms cada) |
| só o algoritmo, 506 skills | **0,03 ms** por rota |
| tamanho do índice | 397 KB |

O orçamento era 100 ms por turno com teto duro de 300 ms. Sobra folga de duas ordens
de grandeza.

**Bug real achado e corrigido nesta sessão:** a geração do sal lia `/dev/urandom`
inteiro com `fs::read`. `/dev/urandom` **não tem fim** — o processo comia toda a
memória da máquina e morria. Virou leitura de 32 bytes. O comentário no código conta
a história, para ninguém "otimizar" de volta.

### 3.2 Bateria de conformidade — `crates/batuta/tests/conformidade.rs`

15 testes que são **o contrato**. Um porte para outra linguagem está conforme quando
passa esta bateria com os mesmos números. Roda com `--test-threads=1` (os testes
compartilham a mesma casa temporária via `BATUTA_CASA`, que é estado global do
processo).

Travam, entre outras coisas: os parâmetros do BM25, o silêncio no ruído, o
determinismo do holdout e a sua proporção em 2000 sorteios, e o fato de o texto do
prompt **não aparecer** no evento.

### 3.3 Bateria v1 — `bateria/v1/tarefas.json`

24 tarefas congeladas: 6 categorias × 4 (1 simples, 2 médias, 1 complexa). As 4 de
`codigo` têm verificador automático. **Os 21 verificadores foram testados de verdade**:
escreveu-se solução de referência para cada um, e todos aprovam a referência e
reprovam quando a solução some (controle negativo). Um furo real foi achado e
corrigido nesse processo (a regra "True ≠ 1" da `cod-04` passava despercebida por
comparação de dicionários).

### 3.4 Protocolo — `docs/PROTOCOLO.md`

O Batuta Zero como procedimento numerado: 5 tarefas × 4 modelos × 2 braços = 40
rodadas. Semente publicada e commitada antes da primeira rodada; ordem sorteada por
`sha256(SEED|tarefa|modelo)`; sessão limpa conferida; anonimização com código opaco e
mapa selado por hash **antes** de julgar; publicação do cru. Mais o juiz (três leis,
pares de julgamento cruzado, rubrica de 3 eixos por categoria) e o holdout causal.
Todos os comandos shell do documento foram executados antes de entrar no arquivo.

### 3.5 Banco Neon — `sql/`

10 tabelas em `sql/001_inicial.sql` mais `batuta.recalcular_metricas_dia(date)`,
idempotente. `sql/002_cadeia.sql` tem triggers que impedem **UPDATE, DELETE e
TRUNCATE** em `batuta.registros`, e `batuta.verificar_cadeia()`.

**Foi subido um Postgres 16 local e tudo foi aplicado, reaplicado e exercitado com
dados.** Reenvio do mesmo dia realmente substitui em vez de duplicar; as três formas
de adulteração levantam exceção.

Três constraints viram lei de banco: `juiz_modelo <> modelo`, juiz sem versão ou sem
hash de prompt é recusado, e tarefa só sai da triagem com enunciado canônico e
critério de aceite.

### 3.6 Portal — `portal/`

Next.js 15 App Router, TypeScript, **build limpo: 18 rotas**, todas estáticas menos as
duas de API.

| rota | estado |
|---|---|
| `/` | pronta — placar honesto, as três peças, para onde vai |
| `/manifesto`, `/spec`, `/protocolo` | prontas — renderizam os markdown do repo |
| `/ranking` | pronta — vazia com o motivo escrito; viés declarado na cara |
| `/receitas` | pronta — vazia com o motivo escrito |
| `/arena` | pronta — formulário funcionando + fila |
| `/registros` | pronta — as três âncoras, e o que a corrente NÃO prova |
| `/privacidade` | pronta — tabela do que fica, exemplo do que sobe, como apagar |
| `/instalar`, `/creditos`, `/doar`, `/404` | prontas |
| `/api/ingest`, `/api/arena` | prontas — **23 casos testados** com os handlers reais |
| `/instalar.sh` | serve o mesmo arquivo do repo |

O `/api/ingest` **rejeita qualquer payload que contenha `prompt`, `prompt_hash`,
`turno` ou `texto` em qualquer nível**, mesmo que o schema passasse: se chegou evento
cru, é bug do cliente, e a resposta diz isso.

**Revisão visual feita**, não só o build: páginas capturadas em 1280px e em 390px e
abertas uma a uma. Dois defeitos reais foram achados e corrigidos assim — o `padding`
em atalho da seção de abertura zerava o respiro lateral no celular (o texto encostava
na borda), e item de lista que quebra em duas linhas no markdown deixava o fim da
frase virar parágrafo solto.

### 3.7 Distribuição — `npm/`, `script/`, `.github/`

`script/instalar.sh` em POSIX puro, com **conferência de SHA256** contra o
`SHA256SUMS` da release (não bate, não instala). `npm/` com zero dependência: abre
tar.gz e zip em JS puro. Dois workflows: `release.yml` (5 alvos, `SHA256SUMS`
consolidado) e `prova.yml` (fmt + clippy + testes).

**Testado ponta a ponta com servidor HTTPS local e release falsa:** instalação boa,
SHA adulterado recusado com exit 1, zip do Windows extraído, wrapper repassando exit
code.

### 3.8 Cadeia de hash — `script/cadeia.mjs`, `registros/`

`anexar`, `verificar`, `ots`. O JSON canônico **bate byte a byte** com o
`json::escrever` do Rust — conferido em 5 saídas reais. As 4 formas de adulteração
(conteúdo, remoção, TOPO, data de fora do lacre) foram pegas com a posição exata.

## 9. As leis do projeto que o próximo chat não pode quebrar

1. **Zero lucro.** Ninguém ganha nada.
2. **O prompt nunca sai da máquina.** Hash com sal local, e o sal não é enviado.
3. **O binário não acessa a rede.** Se precisar de rede, não mora no binário.
4. **Silêncio no ruído.** Falso positivo custa mais que falso negativo.
5. **Voto decide a fila, nunca a nota.**
6. **O juiz é cego, não é réu, e é versionado.**
7. **Existe grupo de controle** — 5%, declarado, configurável, desligável.
8. **A corrente não se edita.**
9. **Viés declarado, sempre.**
10. **Fonte antes do build** — nada de artefato publicado sem remoto com push.
11. **Número medido, não estimado.** Se o n é pequeno, diga o n. "Não sei" é resposta.
12. **Segredo vive só no cofre.** Não se pede e não se cola segredo no chat.
13. **Quando declinar ou limitar algo, o motivo se escreve. Quando publicar, o cru
    acompanha.**
